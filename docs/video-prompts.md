# 视频提示词中的手部动作限制

`VIDEO_PROMPT_SYSTEM` 要求提示词模型把允许的动作和禁止的额外动作直接写入
最终 `video_prompt.txt`，不只用“自然、流畅、稳定”等形容词。

对单次拿起盒子的任务，默认采用以下约束：

| 阶段 | 允许的动作 | 限制的额外动作 |
| --- | --- | --- |
| 接近 | 从实际首帧姿态连续接近，手指仅做抓取所需的张开 | 试探悬停、来回修正、绕圈、敲击、手指乱动、预演抓握 |
| 抓取 | 到达接触位置后，手指协调闭合一次，保持相对接触位置 | 反复捏紧、松开重抓、手指爬动、滑动和轮流调整 |
| 抬起 | 建立抓握后，手和物体一起沿任务指定方向移动 | 横向游移、上下颠动、无要求的腕部或物体旋转 |
| 保持 | 平滑减速到最终位置，保持位置、腕部朝向和手指姿态 | 抖动、摆动、反复稳定、调整抓握和展示性小动作 |

这些约束默认抑制任务没有要求的动作。原任务明确要求的旋转、摇晃、敲击、
重复动作、重新抓握、释放或后续步骤仍然优先；不会强迫所有任务都以抬起保持结束。
阶段之间应自然连续过渡，不把整只手冻结，也不编造秒数、速度或暂停时长。

下一次正常运行 `run` 就会采用更新后的系统提示词。已有输出目录中的提示词和
视频不会被改写。Mock 不进行提示词推理；真实 VLM 的输出仍需检查。
这些是生成约束，不保证视频模型完全遵循。若还要把小动作作为 QC 的任务违例，
应将对应要求写进原始任务；生成提示词不会被传入独立 QC。
